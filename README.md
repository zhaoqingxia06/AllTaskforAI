# TaskArchive · 跨平台任务档案 Skill

把你在不同 AI 平台提出过的真实需求，整理成一个可追溯的网站，并由各平台每天持续更新。

## 使用方式

| 场景 | Skill 完成的事情 |
| --- | --- |
| 没有档案网站 | 整理当前平台可读取的历史需求，创建档案网站，创建该平台每日更新任务，返回网址供你检查 |
| 已有档案网站 | 提供 Skill 和已有网址，将当前平台的历史需求合并进同一个网站，并创建该平台每日更新任务 |
| 每日自动运行 | 获取当前平台新增及变更的请求，按统一规则整理后更新原网站 |

直接运行且未保存网站地址时，Skill 会先问你是否已有档案网站；有则提供网址，没有则新建。已保存地址或已附带网址时不重复询问。用户无需创建、选择或绑定 GitHub 仓库。

首次使用：

> 运行 TaskArchive，整理我在当前平台提出的历史需求，创建任务档案网站，并设置每日更新。

在另一个平台使用：

> 运行 TaskArchive，把当前平台的历史需求合并到我的任务档案：<你的网站地址>，并设置每日更新。

默认每天用户当地时间 12:00；可指定其他时间。每个平台负责自己的采集与定时任务，共同更新一个网站。重复运行复用任务，不重复收录。

## 网站展示

大类别 → 项目／主题（介绍与记录跨度）→ 合并后的需求 → 带时间、平台和会话来源的用户原文。

同一需求的多次补充、修改和修复合并展示；不同平台讨论同一项目时统一归集，保留各来源。支持全文搜索、来源筛选和原文追溯。

## 个人示例

[查看作者的任务档案网站](https://zhaoqingxia06.github.io/AllTaskforAI/)

该网址仅供查看排版示例，不包含在可分享的 Skill 内。Skill 使用自带 HTML 模板固定标题、分类、项目、摘要和原文的排版；运行时无需访问作者网站。

该网站及本仓库根目录现有 data、web、scripts 和 index.html 是作者个人示例，保留用于展示。它不是新用户的默认写入目标，也不随 Skill 初始化复制。网站目前的托管方式不限制 Skill 使用其他网站服务。

## Skill 文件

可分享的完整 Skill 位于 [task-archive/](task-archive/)，入口为 [SKILL.md](task-archive/SKILL.md)。将整个 task-archive 文件夹安装到目标平台支持的 Skills 目录，或按该平台的技能导入方式使用；包含通用规则、导入与构建脚本、HTML 模板、网站接入约定和定时任务提示模板。

## 实际能力边界

- 历史覆盖取决于当前平台提供的读取能力；无接口时可导入用户导出的记录，不能宣称已读取全账号历史。
- 网站必须具有持久存储和经过授权的跨平台更新能力。Skill 会使用实际可用的网站服务；普通只读网址不会自动成为写入接口。
- 定时更新需要平台同时支持调度、读取新增消息和更新网站；能力不足时明确报告未启用。
- 本项目包含 Skill 执行流程与本地导入、校验、HTML 构建工具；尚未提供独立部署的通用跨平台写入后端。安装 Skill 本身不会新增平台权限。

现有个人示例的维护约定见 [ARCHIVE_RULES.md](ARCHIVE_RULES.md) 和 [CONTRIBUTING.md](CONTRIBUTING.md)。
